# Phase 7: all-shapes raycast report loop (`phys_fn_000684` / `000686`)

The census splits one oracle function at its internal alignment boundary:
IDA reports the function beginning at `0x100152e0` and ending at
`0x100153bf`; the rows at RVA `0x152e0` (29 bytes) and `0x15300` (191 bytes)
are its entry and continuation. The candidate implementation is
`nxRaycastAllShapesLoop` in `Physics/src/SceneRaycast.cpp`.

The existing public `NxPhysicsSceneRaycastTests` differential exercises the
loop through static, dynamic, and combined-shape queries, with hit callbacks
that record every report and stop the walk at selected hits. Its registered
coverage includes the all-shapes records for static and dynamic scenes and
the combined (`NX_ALL_SHAPES`) scene.

The clean baseline and restored control both match the shipped oracle exactly:
`oracle_exit=0`, `candidate_exit=0`, `stdout_delta=0`, and exact stderr. A
throwaway no-op mutation that suppresses `report.onHit(hit)` while preserving
the loop changed the differential transcript by 5,140 bytes (`stdout_delta=5140`;
both processes still exit zero and stderr remains exact). This directly
falsifies the report dispatch in the shared entry/continuation function.

Two weaker mutations were deliberately rejected as evidence: suppressing the
loop's internal hit count is not observable because the public wrapper always
returns zero, and removing the shape/distance flag OR is not observable in the
current fixture because the shape vtable already supplies those bits. Only the
callback no-op is used for closure.

The restored Phase 7 gate passes with `coverage_assertions_evaluated=1770`
against floor `1770` and `phase_gate=7 status=pass`. Compressed raw logs are in
`evidence/raw/phase7-raycast-all-shapes-000684-000686-20261013/`.
