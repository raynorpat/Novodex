# Phase 4 triangle-mesh descriptor cases

The public-header-preserving descriptor fixtures were added to `NxPhysicsTriangleMeshApiTests` in `tests/PhysicsTriangleMeshApiTests.cpp`. They drive `TriangleMesh::loadFromDesc` through `NxPhysicsSDK::createTriangleMesh`, then query `saveToDesc` and the cooked arrays. The new cases are registered in `tools/gate_targets.ps1`, so both oracle and candidate must report each fixture, in addition to producing identical transcripts.

The padded 16-bit case uses padded point records, padded 16-bit triangle records, `NX_MF_FLIPNORMALS`, and material indices with a four-byte stride. Oracle output: 4 vertices, 2 triangles, vertex hash `b08a8f02841b2ae5`, triangle hash `15ea361ae49aae26`, saved flags `00000000`, material hash `ed0f2487f3f560b9`. The implicit-index case supplies six point records and no triangle array; the oracle welds duplicate points to 4 vertices and emits 2 triangles. Its hashes are vertex `f9066b93ff223e05`, triangles `15ea361ae49aae26`, flags `00000000`, and the empty-material hash `cbf29ce484222325`.

The first differential found one mismatch: the candidate copied the input winding bit into `saveToDesc` (`flags=00000001`) after the indices had already been flipped, while the oracle returned zero. The listing for `phys_fn_002166` at 0x00053c80 confirms descriptor flags are zero unless the computed convex mesh at `TriangleMesh+0xa0` exists, in which case exactly `NX_MF_CONVEX` (4) is written. `TriangleMesh::saveToDesc` now follows that rule.

After committing and fast-forwarding the fix to local main, rebuilding `NxPhysics.dll` changed its SHA-256 to `bfdb481a74c89a6a7459a0ac15dee0cecd2619c9d1a61df0331b1dca2dd28c76`. The focused mesh API differential passed with `stdout_delta=0` and `stderr_exact=True`. The full Phase 4 gate then passed: immutable public-header checks, inventory validation, Win32 Release build, all three staged-pair targets (`NxPhysicsConvexMeshTests`, `NxPhysicsTriangleMeshApiTests`, `NxPhysicsPMapResolution80Tests`), the Phase 4 oracle-differential targets, and coverage `262/262`.

These fixtures strengthen the evidence for the descriptor-conversion/readback path; they do not close the full 1,044-byte `phys_fn_002260` row or the remaining triangle-mesh lifecycle, model/tree, and contact rows.
