# Phase 5 public actor names

The fresh-process `NxPhysicsActorNameTests` loads the pinned oracle and CMake-built candidate through `NxCreatePhysicsSDK`, creates a static box actor with `NxActorDesc::name`, and calls the public actor and shape name virtuals. The oracle's concrete actor table at image RVA `0x104530` uses slot 83 (`0x2d90`) for `setName` and slot 84 (`0x2d60`) for `getName`; descriptor loading calls `0xedc0` with the actor's body as the name-map key. The candidate now routes descriptor and public actor names through that same body key. Shape names retain their separate shape key.

Both staged DLLs report descriptor and setter pointer identity, replacement, independent shape naming, and clearing: `name_descriptor=1.actor-descriptor`, `name_first=1.actor-first`, `name_second=1.actor-second`, `name_shape_separate=1.1`, `name_cleared=1.1`. The setter/shape/clear sequence adds and frees no allocator blocks because the descriptor name already created the map and its two-slot pair array. Eight lines are registered in Phase 5, raising the assertion floor from 382 to 390. The prior actor lifecycle, dynamic-first, and empty-Scene staged differentials remain exact.

Three aimed mutations were each rebuilt and run through the staged actor-name differential, then restored. Returning null from `getName` changed the descriptor observation to `0.<null>` and produced `stdout_delta=8`. Skipping the public `setName` call changed the first-setter observation to `0.actor-descriptor` and produced `stdout_delta=8`. Skipping descriptor-name propagation changed its observation to `0.<null>` and produced `stdout_delta=4`. The restored control has `stdout_delta=0`. Lock contention, error reporting, and other actor virtual slots remain open.
