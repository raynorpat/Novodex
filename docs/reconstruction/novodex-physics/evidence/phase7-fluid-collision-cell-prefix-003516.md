# Fluid collision cell-prefix accumulator — `phys_fn_003516`

`phys_fn_003516` at RVA `0x86520` is the bucket-to-cell prefix stage in the dirty static-collision builder `phys_fn_003505`. IDA shows a cdecl helper receiving the bucket descriptor. It walks 12-byte bucket rows using the count at descriptor `+8`; each row supplies a signed cell count and first-cell offset. For each referenced 16-byte cell record, the helper stores the descriptor's current total at cell `+12`, adds the pending count at cell `+8` to descriptor `+28`, and clears cell `+8`. It returns the bucket-row count. A zero bucket-row count returns without changing cells or the descriptor total.

`Physics/src/FluidCollision.cpp` implements this contract as `nxFluidCollisionCellPrefix`. `NxPhysicsFluidEmitterAbiTests` calls the pinned oracle at RVA `0x86520` and resolves the candidate function from the current DLL map. Three bucket rows refer to three cells with pending counts `3, 1, 2`; the observed prefixes are `0, 3, 4`, total `6`, return `3`, all pending counts are cleared, bucket rows and unrelated words are preserved, and both x86 stacks balance. The empty-range case preserves its bucket, cell, and total storage and returns zero.

The mutation test stores `totalIndices + 1` instead of `totalIndices` in each cell prefix. The candidate's three prefixes diverge from the oracle while count clearing and total remain correct; the harness reports `prefixes=0, mismatches=1`. Restoring the exact store returns both populated and empty cases to zero mismatches.
