# Fluid emitter paired-array growth failure (`phys_fn_003501`)

The public emitter-creation fixture now reaches both reallocations performed when the internal and public emitter arrays grow from capacity two. It injects failure into the first matching 24-byte allocation and then the second, each in a child process because the shipped append helper faults while copying after allocation failure. Both oracle and candidate report the same observed contract: the first failure leaves the counts at internal/public `2/2`; the second leaves them at `3/2`. In either case, the backend create callback has already run once for the attempted emitter, the failed public call returns through the access violation, and exactly one allocator request is rejected.

A candidate-only mutation reversed the two append operations. The ordinal-two probe detected the changed partial state (`internal=2`, `public=3`, `exact=0`), and the candidate differential failed as expected (`oracle_exit=0`, `candidate_exit=1`, `stdout_delta=4116`). After restoring the implementation, both child probes passed and the full staged simulation transcript matched exactly (`oracle_exit=0`, `candidate_exit=0`, `stdout_delta=0`, `stderr_exact=True`).

Fresh Phase 5, 6, and 7 gates passed with 2,872, 1,732, and 3,011 coverage assertions observed. Phase 6 passed at its updated exact floor of 1,732; Phases 5 and 7 observed all 2,872 and 3,011 registered assertions before their floors were raised to those exact counts. The gate registry suite passes all 39 tests with the updated floors, and the final focused staged-pair differential remains exact. The raw mutation, restored differential, and gate logs are compressed under [evidence/raw/phase7-fluid-emitter-array-growth-003501-20261017](raw/phase7-fluid-emitter-array-growth-003501-20261017/).

This proves paired-array append order and the two growth-failure states only. `phys_fn_003501` remains open for the remaining body and dependency audit. Public Physics headers and production behavior are unchanged.
