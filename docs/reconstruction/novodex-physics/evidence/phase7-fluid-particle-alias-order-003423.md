# `phys_fn_003423` initial-particle channel ordering

IDA at oracle RVA `0x00084a80` shows three ordered passes for a nonempty particle batch: copy positions while zeroing velocity/lifetime and writing cell/sentinel words; copy the optional velocity stream; then copy the optional lifetime stream. Existing tests covered ordinary separate buffers, clipping, nulls, allocation failures, strides, cell quantization, and append behavior, but did not distinguish this ordering from a per-particle copy.

`NxPhysicsFluidParticleAliasOrderTests` makes the order observable with a valid position buffer that aliases the `ParticleArray` backing store. The first particle's zero-velocity store overwrites the next position's X source before the oracle reads it; the later velocity pass must not overwrite that source before the position pass completes. The pinned oracle reports `count=2 second-x=00000000`. The previous candidate order reports `second-x=c0d80000` (`-6.75`) and is rejected (`oracle_exit=0`, `candidate_exit=1`, `stdout_delta=2`). Restoring the three-pass order gives exact output (`oracle_exit=0`, `candidate_exit=0`, `stdout_delta=0`, `stderr_exact=True`). Reintroducing the interleaved velocity/lifetime writes is also rejected by the same registered differential.
