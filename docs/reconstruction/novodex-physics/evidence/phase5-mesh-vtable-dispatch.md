# Mesh primary vtable: transform-center row

The pinned mesh primary table begins at `.rdata` RVA `0x107630`. Its 18 slot RVAs are `28e80, 27740, 256f0, 27f10, 28e10, 29230, 266a0, 29610, 27ec0, 28ed0, 29190, 27e90, 27e30, 27e60, 27f00, 27f00, 27f00, 27e20` (hex). Thus `phys_fn_001403` at `0x29190` belongs to slot 10. Earlier object-model notes and the inventory had mislabeled it slot 4; the existing transcription was also attached to `BoxShape`. It now belongs to `MeshShape` without changing the public headers or the function body.

Slot 10 copies four words from the mesh record at `+0x5c`, transforms the first three through the shape pose, and preserves the fourth. The shape vtable harness compares oracle and candidate output bytes for four nonidentity pose and center inputs. The older layout-harness drive also reports `transpt1403 candidate failures=0` after the class correction.

For slot 9 (`phys_fn_001401` at `0x28ed0`), the no-acceleration-tree branch starts at `0x28fe4`. It reads six local bounds words at mesh `+0x44`, computes centers and half-extents, applies the shape pose, and writes a world AABB. The listing keeps some x87 intermediates extended while rounding others to float before the final stores. A first transcription matched six exact-value cases but failed 58 of 64 fractional cases. After reproducing the listing's store order, 64 oracle/candidate output-byte cases pass.

The tree-backed branch calls the six-direction support search at `0x2d9b0`. The candidate follows each signed pose axis through the mesh's neighbor graph, using the tree's six cached start indices and the owner's visited-stamp scratch record. Eighty-four oracle/candidate drives cover complete graphs, sparse chains, null graph fields, empty neighbor lists, and stamp wraparound; they compare all six output words, cached indices, visited arrays, and stamp words. The slot-9 body is now represented by `MeshShape::nxMeshWorldAABB`, while the general support helper remains inlined here and its other caller at `0x552c0` is still pending.

Mesh slot 7 (`phys_fn_001407` at `0x29610`) returns false and copies mesh `+0x68` to the output when the classifier at mesh `+0xac` is null. With an already built plane table at tree `+0x28`, it transforms the input point into the shape frame, chooses a plane through the classifier lattice, calls `NxRayPlaneIntersect`, and returns true even if that callee reports a parallel ray. Twenty-four oracle/candidate drives cover the null classifier and prepared tables with one-, two-, and three-bin grids and three distinct planes. The lazy table builder at `0x2b6f0` remains open; `nxMeshSweepPrepared` is therefore scoped to already built tables, and the inventory keeps the full slot-7 function at `discovered`.

Mesh slot 0 (`phys_fn_001399` at `0x28e80`) was previously missing both allocator effects. Direct oracle/candidate calls on constructed mesh shapes now check flag 0 and flag 1: both destroy the collision object and decrement a bound mesh refcount from 7 to 6, while flag 1 additionally frees the shape. Allocator free deltas are 1 and 2 on both sides. The candidate's vptr restoration will be installed with the complete mesh table.

Mesh slot 4 (`phys_fn_001397` at `0x28e10`) bypasses mass accumulation when the shape's low flag bits are set. With a nonnegative mass cache at mesh `+0xb0`, it copies the cached frame, applies the shape pose through `0x1c5a0`, merges into the destination, and returns true. Forty-eight oracle/candidate cases cover both bypass flags and the cached path with fractional, nonidentity poses. The first broader run found seven one-to-three-ulp differences in the diagonal inertia words. The shared `MassFrame::nxMassFrameTranslate` now follows the oracle's asymmetric x87 stores for those squares; all 48 cases pass. The negative-cache volume-integral path at `0x54bb0` remains open. The pinned harness transcript is `shape vtable oracle_digest=ed1294b6 cases=626 failures=0`.

The candidate mesh constructor does not yet install an 18-entry table. Its raycast, lazy sweep-table construction, negative-cache mass recomputation, and debug-render rows still require reconstruction and callable-table tests. The Phase 5 gate therefore remains red at `CANDIDATE-MISSING family=vtables`, with the layout harness reporting one overall candidate mismatch. These isolated checks do not close that marker.
