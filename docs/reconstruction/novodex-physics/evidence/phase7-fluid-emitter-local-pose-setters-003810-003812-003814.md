# NpFluidEmitter local-pose setters (`phys_fn_003810`, `003812`, `003814`)

IDA decompilation of oracle RVAs `0x8c660`, `0x8c710`, and `0x8c7c0` shows the write-locked `setLocalPose`, `setLocalPosition`, and `setLocalOrientation` methods update the local pose, publish the resulting backend world pose, and then refresh the cached backend pose at internal `+0x48` through `EmitterGetGlobalPose`. The source already had the local copy and world-pose publication, but omitted that final cache refresh. The shared `nxNpFluidEmitterStoreGlobalPose` helper implements the oracle's 12-word cache copy, so each setter now calls it after publishing its world pose.

The registered `NxPhysicsFluidEmitterAbiTests` fixture now forwards the probe's `setLocalPose` call into production code and compares all 24 words spanning the local and cached world poses, callback records, and x86 stack balance across the pinned oracle, source implementation, and rebuilt candidate DLL. The restored differential reports five cases, five callback checks, five balanced stacks, and zero mismatches. Candidate-only entry mutations replacing each method with `ret 4` are independently rejected: row `003810` reports one mismatch, `003812` one, and `003814` one.

Strengthening that same state comparison exposed the same missing cache refresh in the already reconstructed world setters `003798`, `003800`, and `003802`; those methods were corrected in the same source slice and each now has a refreshed full-state differential. Their candidate-only `ret 4` mutations report 2, 1, and 1 mismatches.
